---
name: Android/Play Store readiness for Expo prebuild CI projects
description: Durable facts about how Mo's GitHub Actions Android build pipeline works — signing, secrets, and config plugin gotchas relevant to any future Play Store submission work.
---

- The checked-in `artifacts/mo-app/android/` folder is **not authoritative**. `.github/workflows/build-android.yml` always runs `expo prebuild --platform android --no-install --clean` first, which deletes and regenerates the native folder from `app.json`/`package.json`. Any signing, manifest, permission, or gradle config fix must go in `app.json` (or a config plugin) — hand-editing the checked-in `android/` folder has no effect on CI builds.
- Expo's prebuild template always emits a debug keystore/signingConfig with fixed credentials: alias `androiddebugkey`, storePassword/keyPassword `android`. A stable replacement keystore (to avoid every CI build requiring users to uninstall before reinstalling) must be generated with those exact same values to be a drop-in — no build.gradle changes needed, since it's the checked-in workflow's own documented recipe.
- Never trust prior session notes about which GitHub Actions repo secrets are configured — verify live via `gh api repos/<owner>/<repo>/actions/secrets` (or `gh secret list`). Found a real case where `ANDROID_KEYSTORE_BASE64` was assumed to exist (per a stale memory note) but had never actually been set, so every prior "signed" APK was actually signed with a fresh ephemeral debug keystore each build.
- `EXPO_PUBLIC_REVENUECAT_*` (or any `EXPO_PUBLIC_*`) env vars used by client code must be explicitly wired into the CI workflow's `expo prebuild` step env — they do not propagate automatically just because they exist as Replit secrets or even as GitHub repo secrets; a missing wire-up silently ships a build where RevenueCat init throws and subscriptions are fully broken.
- `app.json`'s legacy top-level `splash` key is deprecated as of Expo SDK 54; use the `expo-splash-screen` config plugin entry in the `plugins` array instead with the same image/resizeMode/backgroundColor.
- `gh` CLI (authenticated via `GH_TOKEN=$GITHUB_PERSONAL_ACCESS_TOKEN`) can set repo secrets directly (`gh secret set NAME --repo owner/repo` reading from stdin) — simpler than manually doing libsodium sealed-box encryption for the GitHub secrets API.
- A real Android release keystore can be generated in this environment via `keytool` from the nix-installed OpenJDK (not on PATH by default — find it under `/nix/store/*openjdk-21*/bin/keytool`), even though `java`/`keytool` aren't globally on PATH.
